# PostgreSQL Database Code

Below is a complete starter database for your **Smart Campus Resource Booking and Conflict Detection System**.

It includes:

- Users and roles.
- Buildings.
- Resource types.
- Classrooms, laboratories, and halls.
- Features such as projectors and Wi-Fi.
- Bookings.
- Database-level conflict prevention.
- Maintenance blocks.
- Approvals.
- Check-in.
- Notifications.
- Waitlists.
- Audit logs.
- Useful views and sample data.

The code uses PostgreSQL UUIDs, which can be generated with `gen_random_uuid()`. PostgreSQL also supports exclusion constraints for preventing overlapping time ranges. [postgresql](https://www.postgresql.org/docs/current/functions-uuid.html)

***

## 1. Create Database

Run this command in PostgreSQL:

```sql
CREATE DATABASE smart_campus;
```

Then connect to it:

```sql
\c smart_campus;
```

If you are using pgAdmin, create the database and open the Query Tool for `smart_campus`.

## 2.1 Extensions

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;
CREATE EXTENSION IF NOT EXISTS btree_gist;
```

`pgcrypto` supports UUID generation, and `btree_gist` allows equality comparisons such as `resource_id = resource_id` inside a GiST exclusion constraint.

# 3. Users Table

```sql
CREATE TABLE users (
    user_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    full_name VARCHAR(150) NOT NULL,

    email VARCHAR(255) NOT NULL UNIQUE,

    password_hash TEXT NOT NULL,

    phone VARCHAR(20),

    role user_role NOT NULL DEFAULT 'student',

    department VARCHAR(150),

    is_active BOOLEAN NOT NULL DEFAULT TRUE,

    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### Important note

Do not store plain passwords in this table. Store a password hash created using bcrypt or Argon2 in the backend.

# 6. Resources Table

This table stores actual rooms, laboratories, halls, and facilities.

```sql
CREATE TABLE resources (
    resource_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    building_id UUID NOT NULL
        REFERENCES buildings(building_id)
        ON DELETE RESTRICT,

    resource_type_id UUID NOT NULL
        REFERENCES resource_types(resource_type_id)
        ON DELETE RESTRICT,

    name VARCHAR(150) NOT NULL,

    room_number VARCHAR(50),

    floor_number INTEGER,

    capacity INTEGER NOT NULL
        CHECK (capacity > 0),

    status resource_status NOT NULL DEFAULT 'active',

    description TEXT,

    image_url TEXT,

    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),

    UNIQUE (building_id, room_number)
);
```

# 10. Bookings Table

This is the main table of your project.

```sql
CREATE TABLE bookings (
    booking_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    resource_id UUID NOT NULL
        REFERENCES resources(resource_id)
        ON DELETE RESTRICT,

    requested_by UUID NOT NULL
        REFERENCES users(user_id)
        ON DELETE RESTRICT,

    title VARCHAR(200) NOT NULL,

    purpose TEXT,

    department VARCHAR(150),

    attendees_count INTEGER NOT NULL DEFAULT 1
        CHECK (attendees_count > 0),

    start_time TIMESTAMPTZ NOT NULL,

    end_time TIMESTAMPTZ NOT NULL,

    booking_period TSTZRANGE GENERATED ALWAYS AS (
        tstzrange(start_time, end_time, '[)')
    ) STORED,

    status booking_status NOT NULL DEFAULT 'pending',

    approved_by UUID
        REFERENCES users(user_id)
        ON DELETE SET NULL,

    approved_at TIMESTAMPTZ,

    rejection_reason TEXT,

    cancellation_reason TEXT,

    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),

    CHECK (end_time > start_time)
);
```

# 11. Critical Conflict Prevention

This is the most important query in your project.

```sql
ALTER TABLE bookings
ADD CONSTRAINT no_overlapping_active_bookings
EXCLUDE USING GIST (
    resource_id WITH =,
    booking_period WITH &&
)
WHERE (
    status IN ('pending', 'approved')
);
```

This prevents two active bookings for the same resource from overlapping.

### Examples

| Booking 1 | Booking 2 | Result |
|---|---|---|
| 10:00–11:00 | 10:00–11:00 | Rejected |
| 10:00–11:00 | 10:30–11:30 | Rejected |
| 10:00–11:00 | 11:00–12:00 | Accepted |
| Room A101 10:00–11:00 | Room A102 10:00–11:00 | Accepted |

The `[)` range means the starting time is included and the ending time is excluded. PostgreSQL documents exclusion constraints as a way to prevent specified values or ranges from conflicting. [postgresql](https://www.postgresql.org/docs/current/sql-createtable.html)

# 12. Maintenance Blocks Table

This table blocks a resource during repairs, examinations, cleaning, or other unavailable periods.

```sql
CREATE TABLE maintenance_blocks (
    maintenance_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    resource_id UUID NOT NULL
        REFERENCES resources(resource_id)
        ON DELETE CASCADE,

    reason VARCHAR(255) NOT NULL,

    start_time TIMESTAMPTZ NOT NULL,

    end_time TIMESTAMPTZ NOT NULL,

    maintenance_period TSTZRANGE GENERATED ALWAYS AS (
        tstzrange(start_time, end_time, '[)')
    ) STORED,

    created_by UUID NOT NULL
        REFERENCES users(user_id)
        ON DELETE RESTRICT,

    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

    CHECK (end_time > start_time)
);
```

Prevent overlapping maintenance periods:

```sql
ALTER TABLE maintenance_blocks
ADD CONSTRAINT no_overlapping_maintenance
EXCLUDE USING GIST (
    resource_id WITH =,
    maintenance_period WITH &&
);
```

# 19. Updated Timestamp Trigger

This automatically updates `updated_at`.

```sql
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = now();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

Apply the trigger:

```sql
CREATE TRIGGER update_users_updated_at
BEFORE UPDATE ON users
FOR EACH ROW
EXECUTE FUNCTION update_updated_at_column();

CREATE TRIGGER update_buildings_updated_at
```

# 20. Booking History Trigger

This automatically records booking status changes.

```sql
CREATE OR REPLACE FUNCTION record_booking_status_change()
RETURNS TRIGGER AS $$
BEGIN
    IF OLD.status IS DISTINCT FROM NEW.status THEN
        INSERT INTO booking_status_history (
            booking_id,
            old_status,
            new_status,
            changed_by,
            remarks
        )
        VALUES (
            NEW.booking_id,
            OLD.status,
            NEW.status,
            COALESCE(NEW.approved_by, NEW.requested_by),
            'Booking status changed automatically'
        );
    END IF;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

Create the trigger:

```sql
CREATE TRIGGER booking_status_change_trigger
AFTER UPDATE OF status ON bookings
FOR EACH ROW
EXECUTE FUNCTION record_booking_status_change();
```

# 27. Find Available Resources

```sql
SELECT
    r.resource_id,
    r.name,
    rt.name AS resource_type,
    b.name AS building_name,
    r.room_number,
    r.capacity
FROM resources r
JOIN resource_types rt
    ON rt.resource_type_id = r.resource_type_id
JOIN buildings b
    ON b.building_id = r.building_id
WHERE r.status = 'active'
  AND r.capacity >= 40
  AND NOT EXISTS (
      SELECT 1
      FROM bookings bk
      WHERE bk.resource_id = r.resource_id
        AND bk.status IN ('pending', 'approved')
        AND bk.start_time < '2026-09-28 12:00:00+05:30'
        AND bk.end_time > '2026-09-28 10:00:00+05:30'
  )
  AND NOT EXISTS (
      SELECT 1
      FROM maintenance_blocks mb
      WHERE mb.resource_id = r.resource_id
        AND mb.start_time < '2026-09-28 12:00:00+05:30'
        AND mb.end_time > '2026-09-28 10:00:00+05:30'
  )
ORDER BY r.capacity;
```

```sql
UPDATE bookings
SET
    status = 'no_show',
    updated_at = now()

  AND start_time < now() - INTERVAL '15 minutes'
```

# 35. Utilization Report

```sql
SELECT
    r.name AS resource_name,
    rt.name AS resource_type,
    b.name AS building_name,
    COUNT(bk.booking_id) AS total_bookings,

    COALESCE(
        ROUND(
            SUM(
                EXTRACT(
                    EPOCH FROM (bk.end_time - bk.start_time)
                ) / 3600
            )::numeric,
            2
        ),
        0
    ) AS total_booked_hours

FROM resources r
JOIN resource_types rt
    ON rt.resource_type_id = r.resource_type_id
JOIN buildings b
    ON b.building_id = r.building_id
LEFT JOIN bookings bk
    ON bk.resource_id = r.resource_id
   AND bk.status IN ('approved', 'completed')

GROUP BY
    r.resource_id,
    r.name,
    rt.name,
    b.name

ORDER BY total_booked_hours DESC;
```

# 38. Useful Database View

```sql
CREATE OR REPLACE VIEW booking_details_view AS

    ON u.user_id = b.requested_by;
```

# 41. Important Correction for Your Backend

When your backend tries to create a conflicting booking, PostgreSQL will return exclusion-constraint error code:

```text
23P01
```

Handle it like this:

```javascript
if (error.code === "23P01") {
  return res.status(409).json({
    success: false,
    error: "RESOURCE_CONFLICT",
    message: "The resource is already booked during this time."
  });
}
```

HTTP status `409 Conflict` is appropriate because the request conflicts with the current state of the resource.
